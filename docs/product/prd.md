# 产品需求 · 冰箱助手 MVP

> 这是 PRD v1.0 的**修订版**。原稿里四条技术事实已过时，见文末「修订记录」。产品目标与三条原则未改。

## 1. 定位

用户打开微信小程序，对着冰箱逐层拍 3 张照片，AI 跨图识别食材并推断库存增减；临期自动提醒；按现有食材推荐食谱。
全程图片用完即弃，服务器只存结构化结果。

### 三条不可妥协的原则

1. **图片零服务器存储**。临时路径与内存里流转，Base64 直发模型，请求结束即释放。Supabase 不存图。
2. **API Key 不进前端制品、不明文落本地**。Key 经云函数加密存，调用时云函数解密转发；前端只拿得到末四位提示。
3. **不逐项确认，例外驱动**。库存由"观测层 → 状态机"推断，默认零点击；只在低置信、不可逆删除、数量突变时轻提示，且可撤回。

## 2. 用户与场景

| 场景 | 触发 | 期望 |
| --- | --- | --- |
| 周末补货后入库 | 拎着购物袋回家 | 拍三层，10 秒内看到"新增 5 项"的摘要，不用一项项点 |
| 做饭前看看有什么 | 下班回家 | 首页概览 + 3 天内到期清单，直接生成"今晚吃什么" |
| 临期别浪费 | 每天早上 | 订阅消息推一条：牛奶明天到期 |
| 拍漏了一层 | 下次盘点 | 没拍到的食材不会立刻消失，连续漏拍 2~3 次才降级，还能一键恢复 |

## 3. 功能范围

### P0（MVP 已实现）

- 三视角引导拍摄（正面全景 / 上层 / 下层），逐张压缩后上传
- 跨图对齐的食物识别，输出统一观测清单（含低置信 `uncertain`）
- 库存状态机推断：新建 / 更新 / 缺失计数 / 降级 / 恢复 / 数量突变待确认
- 变更摘要卡（零点击），需要点的那一行才出现按钮
- 临期提醒：每日定时扫描，3 天 / 1 天 / 已过期三级，订阅消息推送，同一天不重复
- 食谱推荐：3 道菜，优先消耗临期与"可能已取出"的食材，标注已有/缺少
- Provider 配置：base_url / model_name / api_key，Key 加密存储

### P1 / P2（未做）

条码扫描、家庭成员共享、购物清单、浪费统计、自训练模型、流式输出。

## 4. 非功能需求

| 维度 | 目标 |
| --- | --- |
| 速度 | 3 张图一轮识别 ≤ 15 秒（P90）；前端本地兜底 60 秒 |
| 成本 | 一次盘点 ≈ 0.01~0.03 元（deepseek-flash，5 图 + 1 次 JSON 输出） |
| 隐私 | 不存储用户照片；Key 仅密文落库；`config.get` 不返回密钥 |
| 可靠性 | 超时/解析失败不写半成品数据；库存降级可撤回 |
| 体积 | 小程序主包 < 2 MB（当前 dist 约 737 KB） |
