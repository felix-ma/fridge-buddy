# 背景

选 Taro 的主要理由之一是"一套代码多端"。但当前只在微信端验证过，跨端的差异点（云开发、媒体 API、订阅消息）都还没处理。

## 目标

- `taro build --type h5` 与 `--type alipay` 能产出可运行版本
- 关键链路（拍照/选图 → 识别 → 库存）在多端可用，或明确不支持并降级

## 范围

**做**：平台适配层（`src/platform/`）、云开发替代方案、媒体 API 差异封装、样式兼容。

**不做**：多端登录体系打通、支付宝订阅消息（先只做站内提醒）。

## 待决问题

1. 非微信端如何调用云函数？可选：自建 HTTP 网关 + 自签 token；或部署 Supabase Edge Function；需要新 ADR。
2. 图片零存储原则在 H5 上同样适用，但浏览器端需要 `canvas` 压缩路径。
3. NutUI 组件在小程序端与 H5 端样式差异需要回归。

## 验收标准

- [ ] AC1 `npm run build:h5` 成功且首屏可渲染（人工）
- [ ] AC2 H5 端选图 + 识别链路可用，或给出明确「请在微信中打开」的降级提示
- [ ] AC3 微信端功能不回归（spec 001~004 验收仍通过）

## 风险

- 跨端适配成本可能高于收益；在真实需求出现前保持 `draft`，不投入。
